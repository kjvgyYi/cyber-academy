## Learning Objectives

После урока ты сможешь:

- Объяснить каждое из трёх свойств CIA своими словами и привести пример нарушения.
- Для любого security-инцидента определить, какое свойство CIA пострадало.
- Объяснить, почему CIA — это компромисс, а не максимум всех трёх.
- Назвать расширения модели (AAA, Parkerian Hexad) и зачем они появились.

## Theory

### Почему CIA — фундамент

Каждое решение в информационной безопасности — шифрование, контроль доступа, резервные копии, мониторинг — существует, чтобы сохранить хотя бы одно из трёх свойств: **конфиденциальность, целостность или доступность**. CIA — это не просто аббревиатура, это вопросы, которые задают при анализе любой угрозы:

1. Могут ли посторонние **прочитать** данные или доступ к ним?
2. Могут ли посторонние (или система) **незаметно изменить** данные?
3. Могут ли законные пользователи **получить доступ**, когда нужно?

Если на все три вопроса ответ «нет» — система в относительной безопасности.

---

### Confidentiality — конфиденциальность

**Определение:** данные доступны только тем, кому они предназначены.

**Нарушение:** утечка базы данных клиентов, перехват незашифрованного трафика, подобранный пароль, кража ноутбука с незашифрованным диском.

**Механизмы защиты:**

| Механизм | Что делает |
|---|---|
| Шифрование | Данные нечитаемы без ключа (AES-256, TLS) |
| Аутентификация | Проверяет, кто ты (пароль, MFA, сертификат) |
| Авторизация | Определяет, что тебе можно читать (ACL, RBAC) |
| Классификация данных | Разграничивает, что «секретно», что «публично» |
| DLP | Data Loss Prevention — следит за утечками |

```info Типичный вектор атаки на Confidentiality
Phishing → пользователь кликает ссылку → атакующий получает сессионный cookie → читает почту жертвы. Шифрование передачи (HTTPS) здесь не помогло: атакующий получил легальную сессию.
```

---

### Integrity — целостность

**Определение:** данные не изменились без авторизованного действия. Изменения отслеживаемы и доказуемы.

**Нарушение:** подмена файла на сервере, man-in-the-middle изменяет банковский перевод в transit, скомпрометированный разработчик добавляет backdoor в код, неправильная запись в лог из-за ошибки.

**Механизмы защиты:**

| Механизм | Что делает |
|---|---|
| Хеш-суммы (SHA-256) | Любое изменение файла → другой хеш |
| Цифровая подпись | Доказывает, что файл создан конкретным ключом |
| TLS (HTTPS) | Предотвращает изменение трафика на пути |
| File Integrity Monitoring | Отслеживает изменения файлов в реальном времени |
| Неизменяемые логи | Append-only хранилища, blockchain-based audit trail |

```info Supply chain attack и Integrity
В 2020 году атака SolarWinds: злоумышленники внедрили backdoor в официальное обновление ПО. Тысячи организаций установили «легальный» дистрибутив с подписью от SolarWinds — нарушение Integrity на уровне цепочки поставок.
```

---

### Availability — доступность

**Определение:** система работает и даёт ответ законным пользователям в разумное время.

**Нарушение:** DDoS-атака, ransomware зашифровал файлы, отказ жёсткого диска без резервных копий, неправильное обновление положило сервис.

**Механизмы защиты:**

| Механизм | Что делает |
|---|---|
| Резервные копии (3-2-1) | 3 копии, 2 носителя, 1 офсайт |
| Redundancy / HA | Несколько серверов, нет single point of failure |
| DDoS-защита | Фильтрация мусорного трафика (Cloudflare, Akamai) |
| Rate limiting | Ограничение запросов per IP / per user |
| Disaster Recovery Plan | Задокументированный план восстановления |

```warning Ransomware и Availability
Шифровальщик часто нарушает и Availability (данные недоступны), и Confidentiality (атакующий скопировал перед шифрованием). Backup — это защита Availability, но если backup тоже зашифрован (потому что примонтирован), он не помогает. Правило 3-2-1: хотя бы одна копия офлайн.
```

---

### CIA как компромисс

Максимальная безопасность по всем трём осям сразу невозможна. Каждое усиление одного свойства снижает другое:

| Действие | Что усиливает | Что ослабляет |
|---|---|---|
| Шифруем всё, ключи у одного человека | Confidentiality | Availability (человек заболел — данные недоступны) |
| Отключаем интернет у серверов | Confidentiality, Integrity | Availability (обновления, удалённый доступ) |
| Открываем систему всем без пароля | Availability | Confidentiality, Integrity |
| Backup каждые 5 минут | Availability | (нагрузка на диск → риск Availability) |

**Вывод:** задача security-специалиста — найти баланс под конкретные требования бизнеса, не максимизировать всё сразу.

---

### Расширения модели

**AAA (Authentication, Authorization, Accounting)** — три шага контроля доступа:
- **Authentication** — кто ты? (логин + пароль, MFA)
- **Authorization** — что тебе можно? (роли, права)
- **Accounting** — что ты сделал? (логи, аудит)

**Parkerian Hexad** (1998) добавляет к CIA ещё три свойства:
- **Possession** — физическое владение носителем (флешку украли, даже если данные зашифрованы — это потеря Possession)
- **Authenticity** — данные действительно от заявленного источника (цифровая подпись)
- **Utility** — данные в пригодном для использования формате (зашифрованный backup без ключа — бесполезен)

На практике в большинстве компаний используют CIA + AAA. Parkerian Hexad — академический контекст и глубокий аудит.

## Example

**Инцидент: взлом Twitch (2021)**

В октябре 2021 года утекло ~125 ГБ данных Twitch: исходный код, внутренние инструменты, выплаты стримерам.

| Свойство CIA | Нарушено? | Почему |
|---|---|---|
| Confidentiality | ✅ Да | Приватный код и финансовые данные стали публичными |
| Integrity | Частично | Данные скопированы, не изменены в системе |
| Availability | ❌ Нет | Сервис продолжал работать |

Атака была направлена прежде всего на **Confidentiality**. Вектор — ошибка в конфигурации сервера (misconfiguration), открывшая доступ к внутренним репозиториям.

```task
  - Изменение суммы = данные стали другими без авторизованного действия.

  1. Confidentiality — посторонний читает данные.
  2. Availability — система недоступна законным пользователям.
  3. Integrity — данные изменены без авторизации.
  4. Confidentiality + Availability — данные скопированы (C) и недоступны (A).
  5. Confidentiality — секрет стал публичным.
```

## Common Mistakes

| Ошибка | Почему неверно |
|---|---|
| «CIA — это про шифрование» | Шифрование — один из механизмов Confidentiality, а не сама CIA |
| «Availability не про security» | DDoS и ransomware — security-атаки на Availability |
| «Если данные зашифрованы, Integrity обеспечена» | Шифрование ≠ защита от изменения; нужны HMAC/цифровая подпись |
| «Нарушение всегда одно свойство» | Ransomware = Confidentiality + Availability; многие атаки комбинированные |

## Summary

- **CIA** — три фундаментальных свойства: Confidentiality (только авторизованные читают), Integrity (данные не изменены тайком), Availability (система работает, когда нужна).
- Для каждого свойства есть набор механизмов защиты; ни один механизм не защищает от всего.
- CIA — это **компромисс**: усиление одного нередко ослабляет другое.
- **AAA** дополняет CIA контролем доступа; Parkerian Hexad расширяет модель для глубокого аудита.
- При анализе любого инцидента первый вопрос: «Какое свойство CIA пострадало?»
